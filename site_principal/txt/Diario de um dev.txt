################# HEADER ################# 

Nota Técnica — Ajustes do Header (Desktop e Mobile)
Objetivo
O objetivo dessa etapa foi construir um header fixo, responsivo e estável, garantindo que:
- o header não cubra o conteúdo (hero)
- não existam espaços em branco gigantes
- o layout funcione corretamente no desktop e no mobile
- o código fique limpo e previsível, sem gambiarras

Problemas encontrados:

1- Header fixo cobrindo o hero
O header usa `position: fixed`, o que remove ele do fluxo normal da página.  
Com isso, o conteúdo (hero) acabava ficando “por baixo” do header.

2- Espaçamentos inconsistentes
Foram identificados vários problemas de espaçamento:

- `padding-top` duplicado no `body`
- `padding` duplicado no `.hero`
- valores muito altos (ex: `250px`) no mobile
- regras se sobrescrevendo dentro do mesmo `@media`

Isso causava comportamentos imprevisíveis:
- em tela cheia ficava errado
- em meia tela ficava certo
- no mobile quebrava tudo

3- Logo quebrando o layout no mobile
O logo estava:
- fora de um agrupamento lógico
- posicionado "acima" do nome da empresa
- deixando o header muito alto no mobile

Resultado: layout “tronxo” e difícil de controlar.

4- Media queries desorganizadas
Havia:
- regras repetidas dentro do mesmo `@media`
- propriedades iguais definidas várias vezes
- dificuldade de entender qual regra realmente estava ativa

Soluções aplicadas:
->Estrutura correta do header
Criei um agrupamento lógico para a marca:
- logo
- nome da empresa
- slogan

O logo passou a ficar "ao lado do nome", tanto no desktop quanto no mobile.  
Isso reduziu a altura do header e estabilizou o layout.

Compensação correta do header fixo
Mantive o header como `position: fixed`, mas corrigi a compensação:
```css
body {
    padding-top: <altura real do header>;
}

################# BLOG ################# 

1- Estrutura do Blog (HTML)
Nesta etapa foi criada a seção de Blog da página principal, com o objetivo de apresentar conteúdos informativos e educativos logo na home.
A seção principal é definida pela <div class="blog">, que funciona como o container geral do blog.

Dentro dela, foi adicionado um título principal (<h1>), deixando claro que se trata do blog da Nordeste Ferramentas.
O conteúdo do blog é organizado dentro da <div class="blog_box">, que agrupa todas as publicações.
Cada publicação é representada por uma <div class="blog_card">, criando a estrutura de cards.

Cada card contém:
.blog_img → responsável por exibir a imagem de destaque do post.
.blog_tag → área de conteúdo textual, com:
<h2> → título do post
<p> → texto introdutório do tema
.blog_icon → ícones visuais (data e curtida), preparando o layout para futuras interações.

2- Estilização do Blog (CSS)

No CSS, a estilização foi feita de forma modular, seguindo a estrutura do HTML.
.blog define o espaçamento geral da seção na página.
.blog h1 centraliza o título do blog, aumenta o tamanho da fonte e aplica a cor azul da marca, mantendo identidade visual.
.blog_box utiliza CSS Grid (grid-template-columns: 1fr 1fr 1fr) para exibir 3 cards lado a lado, criando um layout limpo e organizado no desktop.
.blog_card recebe:
-largura fixa
-sombra (box-shadow) com tom alaranjado, reforçando a identidade visual

.blog_img controla o tamanho da imagem e usa overflow: hidden para manter o enquadramento correto.
A imagem (img) usa object-fit: cover, garantindo que a imagem preencha o espaço sem distorcer.
.blog_tag define o espaçamento interno do texto.
O título do card (h2) recebe a cor laranja, destacando os temas.
O parágrafo (p) usa text-align: justify e line-height para melhorar a leitura.
.blog_icon usa flex para alinhar os ícones nas extremidades, já preparando o layout para futuras funcionalidades (data real, likes, interações com JS).

3-Ajustes Mobile — Seção Blog

Problemas identificados no mobile
- O layout em 3 colunas ficava espremido em telas pequenas.
- Os cards tinham largura fixa (450px), causando quebra do layout.
- As imagens não se adaptavam bem ao tamanho da tela.
- O texto ficava visualmente pesado para leitura no celular.

Soluções aplicadas

Estrutura em coluna única
- No mobile, o grid do blog foi alterado para 1 coluna:
- Cada publicação aparece uma abaixo da outra.
- Layout semelhante ao Hero, mais natural para scroll vertical.

Remoção de larguras fixas
- A largura fixa dos cards foi sobrescrita no mobile.
- Os cards passaram a ocupar 100% da largura disponível, evitando estouros horizontais.

Ajuste das imagens
- As imagens do blog passaram a:
- ocupar 100% da largura do card
- ter altura controlada

Tipografia otimizada
- O título principal do blog (`h1`) teve o tamanho reduzido.
- Os títulos dos cards (`h2`) e os parágrafos (`p`) ficaram mais confortáveis para leitura em telas pequenas.

Espaçamento e respiro visual
- Espaçamentos entre cards foram ajustados.
- Margens e paddings foram refinados para evitar poluição visual.

Resultado final
- Blog totalmente funcional no mobile
- Leitura fluida e agradável
- Layout consistente com o Hero
- Base pronta para futuras interações com JavaScript

!! Ajuste de alinhamento da lista (mobile – seção “Sobre”)

Durante o ajuste da versão mobile da seção Sobre a Nordeste Ferramentas, surgiu um problema visual na lista de benefícios (ícones + texto).
As linhas não iniciavam na mesma margem, deixando o layout desalinhado e com aparência “quebrada”.

Problema identificado
No CSS mobile, a classe .feature estava usando:
justify-content: center;

Isso fazia com que cada item da lista fosse centralizado como um bloco, anulando qualquer tentativa de alinhar os textos pela esquerda.
Mesmo adicionando novas regras, o comportamento não mudava porque essa propriedade tinha prioridade no layout flex.

Solução aplicada
A correção foi feita somente no mobile, substituindo o alinhamento central por alinhamento à esquerda e garantindo largura total do item:

.feature {
    justify-content: flex-start;
    text-align: left;
    width: 100%;
}

Além disso, foi padronizada a largura do ícone para garantir alinhamento consistente entre todas as linhas:

.feature i {
    width: 22px;
    min-width: 22px;
    text-align: center;
}

Resultado

Todos os itens da lista passaram a começar exatamente na mesma margem
Ícones e textos ficaram perfeitamente alinhados
Layout mobile ficou limpo, organizado e profissional
O desktop não foi afetado

/*Aprendizado
Quando uma alteração visual “não funciona”, geralmente existe uma regra anterior anulando o comportamento esperado.
Antes de adicionar mais CSS, é essencial verificar qual propriedade está dominando o layout.*/

################# Votei pra caaaaaa #################

Domingao de `Amarrando as pontas soltas`
Depois de alguns dias focando em construir o site, hoje foi aquele dia de fazer o que muita gente nem percebe quando vê um projeto pronto: revisar, testar e corrigir pequenos detalhes. Não foi um dia de criar páginas novas, mas sim de transformar um projeto funcional em um projeto muito mais organizado e profissional.
Comecei revisando todo o HTML do site institucional da Nordeste Ferramentas. A ideia era conferir se todos os links, botões e seções estavam funcionando corretamente antes de considerar essa etapa encerrada. Durante essa revisão encontrei alguns pequenos problemas que acabaram rendendo boas lições.
O primeiro deles foi o botão Início, que simplesmente parou de levar o usuário ao topo da página. A princípio achei que o problema estava no próprio link da âncora, mas depois de investigar percebi que o destino dela era o <header>, que estava com position: fixed. Isso fazia o navegador entender que ele já estava no topo.
Antes:
<header class="header" id="inicio">

Depois:
<body id="inicio">
<header class="header">

Uma mudança pequena, mas que resolveu completamente a navegação.
Também aproveitei para integrar de vez o site institucional com o NF Blog. Todos os acessos ao blog agora são abertos em uma nova aba, permitindo que o usuário continue com o site principal aberto enquanto navega pelo conteúdo.
Antes:
<a href="../nf_blog/index.html">
    BLOG
</a>

Depois:
<a href="../nf_blog/index.html"
   target="_blank"
   rel="noopener noreferrer">
    BLOG
</a>

Além de melhorar a experiência do usuário, essa alteração segue uma boa prática de segurança ao utilizar target="_blank".
Enquanto revisava os botões percebi que alguns possuíam uma borda preta enquanto outros não. O visual ficava estranho porque cada botão parecia pertencer a um estilo diferente. A solução foi padronizar todos eles no CSS.

Antes:
.blog-btn{
    border: 2px solid #000;
}
.equipamentos-actions .btn-primary{
    border: 2px solid #000;
}

Depois:
.btn-primary,
.btn-secondary,
button{
    border: none;
    outline: none;
}

Com isso todos passaram a seguir exatamente o mesmo padrão visual.
Quando achei que estava tudo pronto apareceu um detalhe curioso. O botão BLOG da barra de navegação ficava roxo depois de ser clicado. Demorei alguns minutos até perceber que ele nem sequer utilizava a mesma classe dos outros links da navbar.
Antes:
<a href="../nf_blog/index.html" class="btn">
    BLOG
</a>

Depois:
<a href="../nf_blog/index.html"
   class="nav-btn">
    BLOG
